# Issue 留言转达

给 Issue 添加精确标签 `给小澪的留言`。下一次已有随机来信或小龙娘日常来信到达发送时间时，机器人读取这些 Issue 的正文和所有新评论，将作者、完整原文和 GitHub 链接作为纯文本附在邮件末尾。开放和已关闭 Issue 都读取；PR 不读取。首次启用会转达当前所有尚未记录的留言。测试、自定义及漫画任务保持原行为，不附加留言。

若标签尚不存在，请在仓库 Issues 的 Labels 页面创建。程序不创建标签、不回复或关闭 Issue，也不产生额外发送任务。留言不会提前触发邮件；现有任务仍由统一队列调度。GitHub Actions 不保证精确发送时间。

## 隔离与状态

`scripts/issue_relay.py` 单独负责 GitHub 只读分页、校验、纯文本拼接、留言占用与确认。内容不交给模型，也不进入命令、模板、邮件头或日志。链接由仓库身份及整数编号构造，不采用留言提供的网址。留言编辑不会改变 Issue/评论 ID，因此同一条留言编辑后不再转达；后续新评论有独立 ID。

发送前，模块通过原有 TaskStore SHA compare-and-swap 更新任务的 `issue_relay`，一次最多占用 20 条、累计原文最多 64000 字符，剩余内容留到后续日常邮件。并发任务会排除已有占用。原文不会截断；单条超过 12000 字符、读取分页超限或 GitHub 读取失败，会停止本次发送并记录失败。

SMTP accepted 和 `issue_delivered` 在 **同一次账本原子写入**中确认。`issue_delivered` 不跟随最多 20 条的发送历史截断，不能清空或删除含去重记录的旧任务。SMTP 失败或发送前过期不会标记已转达，留言可由之后的新日常任务领取；失败任务本身不会重试。SMTP 不确定、运行中断、取消正在发送的任务或结果写入未确认时，保留占用且不标记已转达，也不自动释放给其他任务。需要人工核验后再决定如何处理；目前未提供自动人工确认工具。

账本包含公开 Issue 文本的发送前快照。不要在公开 Issue 发布邮箱密码、授权码或其他隐私。SMTP 接受仅表示服务器接受，不代表收件箱已收到。

## 配置与验证

统一 tasks job 增加最小 `issues: read` 权限；沿用现有 GitHub 内置令牌和 QQ SMTP Secrets，没有新密钥。部署不会创建计划，也不会自行发送测试邮件。若其他执行环境使用细粒度 PAT，需要同时具有 Issues 只读权限。

离线测试：`python -m unittest discover -s tests -q`。覆盖分页、PR 排除、原文安全、并发占用、成功去重、失败释放、不确定保护、状态写入失败、周期任务以及正文拼接；测试不连接 SMTP 或 GitHub。
